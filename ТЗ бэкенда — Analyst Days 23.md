# ТЗ бэкенда — Analyst Days 23

Сервис должен ответить на два вопроса очного участника конференции. Какие выступления за оба дня подходят под его темы? Какие из них останутся в маршруте, если он уже выбрал зал на конкретное время? До ручного выбора сервис возвращает все подходящие варианты. Фронтенд использует один и тот же ответ для подсветки сетки и скачивания PNG.

**Результат разработки** — самостоятельный HTTP API на Python и FastAPI в репозитории `analyst-days-23-backend`, проверенный снимок программы в SQLite с доступом через SQLAlchemy и общий процесс выпуска двух компонентов. В SQLite хранится публичная программа. Персональный выбор живёт в пределах запроса. [Сценарий MVP](<Сценарий MVP — Очная траектория Analyst Days 23.md>) · [ТЗ фронтенда](<ТЗ фронтенда — Analyst Days 23.md>)

## Снимок программы

Подготовить полную программу 20 и 21 ноября 2026 года в часовом поясе `Europe/Moscow`. Загрузить четыре зала A–D, темы официальной легенды, названия и подписи выступающих. Для блица и каждой части мастер-класса записывать отдельный непрерывный интервал с фактическим временем. Общую активность, повторённую в нескольких колонках программы, загрузить один раз. [Схема SQLite, ER-диаграмма и источник расписания](<Данные/Модель данных — Программа Analyst Days 23.md>)

- `room` и `topic` — справочники залов и тем со стабильными идентификаторами и названиями. `entry` — карточка с видом, датой, интервалом, заголовком, подписью выступающих, залом и ссылкой `previous_part_id`. Исправление заголовка или имени сохраняет ID карточки.
- `entry_topic` связывает карточки и темы. Составной первичный ключ запрещает повтор пары. У выступления обязателен зал. Для общей активности вида `break`, `service` или `hackathon` допустим `room_id: null`.
- При импорте включить внешние ключи. Проверить оба дня, четыре зала, допустимые значения и положительную длительность. У продолжения должен быть один непосредственный предшественник того же мастер-класса, завершающийся к началу продолжения. Поле `previous_part_id` уникально для непустых значений. Цепочка идёт вперёд по времени без циклов и ветвлений.
- Завершать загрузку и проверки одной транзакцией. При ошибке сохранить предыдущий пригодный снимок. Процесс API открывает опубликованный файл только для чтения. Одна `revision` обозначает всё содержимое выдаваемой программы. Она стабильна после перезапуска и одинакова на разных экземплярах для одного содержимого. Правка интервала, подписи, темы или связи меняет версию.

## HTTP API

Три анонимные операции обслуживаются с того же публичного адреса, что и сайт. Точные имена полей, типы, ограничения, коды и примеры определены в [OpenAPI 3.1](API/openapi.yaml). [Семантика запросов и ответов](<API/Контракт API — Очная траектория Analyst Days 23.md>)

- **`GET /api/health`** проверяет возможность прочитать пригодный снимок. Успех — `200 {"status":"ok"}`, недоступность снимка — `503 program_unavailable`.
- **`GET /api/program`** возвращает `200` с `revision`, `timezone`, `days`, `rooms`, `topics` и `entries` одного снимка. В каждой карточке собрать `topic_ids` из таблицы связей. Сортировать карточки по дате, началу, залу и ID. При равном времени общая полоса идёт первой. При недоступном снимке вернуть `503 program_unavailable`.
- **`POST /api/trajectory/preview`** принимает `revision`, массив уникальных `topic_ids` и массив `actions`. Каждый элемент `actions` содержит `op` и `entry_id`. При успехе вернуть `200`, заголовок `Cache-Control: no-store` и JSON с той же `revision`, массивом `items` и признаком `is_custom`. Каждый элемент `items` содержит ровно один `entry_id`, его `state` и массив `conflicts_with`. Порядок элементов соответствует сетке. Запрос полностью описывает выбор и даёт воспроизводимый результат при повторе.

### Расчёт траектории

1. Для обоих дней сформировать базовую подборку по совпадению хотя бы одной темы. Участвуют `talk`, `blitz`, `discussion` и первые части `workshop`. Пустой список тем даёт пустую подборку. Перерывы, служебные события и хакатон остаются в расписании.
2. Применять действия в переданном порядке. При `choose` включить выбранную карточку независимо от фильтра. Если это продолжение, включить всю цепочку от начала до выбранной части. Для каждой включаемой части убрать остальные карточки, занятые в её интервале, и продолжения, потерявшие обязательную часть. Промежуток между частями остаётся свободным. Клик по началу сам по себе выбирает только начало. Повторный выбор уже разрешённой карточки сохраняет результат.
3. Две карточки пересекаются в пределах **одной даты**, когда `a.starts_at < b.ends_at` и `b.starts_at < a.ends_at`. Зал на проверку не влияет. Блицы 16:30–16:50 и 16:50–17:10 можно посетить подряд. Занятие 16:30–17:10 в другом зале пересекается с каждым из них.
4. При `skip_continuation` убрать указанную часть и все зависящие от неё продолжения. Сохранить более ранние части. Повторный пропуск отсутствующего продолжения даёт тот же состав. Освободившееся время остаётся свободным до следующего выбора или нового расчёта по фильтру.
5. Для каждой включённой карточки перечислить ID всех её прямых пересечений среди остальных включённых карточек. Связь симметрична. Пустой список даёт `selected`, непустой — `alternative`. В примере с длинным занятием и двумя блицами каждый блиц связан только с длинным занятием.
6. Сравнить итоговый состав и статусы с базовой подборкой по тем же темам. Вернуть `is_custom: true` только при отличии. Выбор уже включённого одиночного доклада может оставить `is_custom: false`. Пустой массив действий восстанавливает базовую подборку без обращения к истории пользователя.

### Ошибки

Тело ожидаемой ошибки содержит стабильный `code` и непустое русское `message`. Ошибка любого действия отклоняет запрос целиком. Во внешнем ответе исключить трассировку и внутренние пути.

- `422 invalid_request` — неразбираемый JSON, пропущенное или лишнее поле, неверный тип, неизвестная операция, повтор темы либо иное нарушение входной схемы.
- `503 program_unavailable` — сервису недоступен пригодный снимок.
- `409 stale_program` — форма запроса корректна, но `revision` устарела. Проверить версию **до поиска идентификаторов**. Даже если старый ID исчез, клиент должен получить предложение загрузить новую программу.
- `422 unknown_topic` или `422 unknown_entry` — такого ID темы или карточки нет в текущей версии. `422 not_selectable` — действие над перерывом, служебным событием или хакатоном. `422 not_continuation` — попытка пропустить выбираемую карточку без предыдущей части.

## Приёмка API и данных

1. **Выбор зала.** Получить действительные ID и `revision` из `GET /api/program`. Передать тему «ИИ» и `actions: []`. На 21 ноября в 16:30–17:10 МСК Дмитрий Неверов (A) и Вера Бонарева (B) имеют `alternative`, ссылаются друг на друга и входят в PNG как варианты. Передать те же темы и `choose` для Бонаревой. В этом интервале остаётся только Бонарева в зале B со статусом `selected` и пустым `conflicts_with`, `is_custom: true`. Другой день сохраняет свой выбор. Повтор запроса даёт тот же результат, сброс действий возвращает оба варианта. Проверять этот интервал внутри полной выдачи обоих дней.
2. **Интервалы и зависимости.** Проверить два смежных блица и замену обоих длинным занятием. Для мастер-класса с перерывом проверить подбор только начала по теме, выбор продолжения с добавлением начала и сохранением занятия в паузе, пропуск продолжения и вытеснение начала другим докладом. Зависимое продолжение при вытеснении также исчезает.
3. **Валидация и хранение.** Проверить каждый предусмотренный код, включая устаревшую версию с исчезнувшим ID и невалидное последнее действие в массиве. На недоступном снимке все три операции при корректном входе дают `503`. Сравнить четыре таблицы и `revision` до и после выбора, пересчёта и скачивания. Отдельно проверить сохранность предыдущего снимка после ошибки импорта.
4. **Публичный Swagger.** FastAPI генерирует `/api/openapi.json` из зарегистрированных маршрутов и моделей. `/api/docs` открывает Swagger UI без входа. Через **Try it out** получить программу, перенести её версию и ID темы «ИИ» в preview и сверить варианты на 16:30. Повторить без поля `revision` — ожидается `422 invalid_request`. После успешной проверки указать действующую ссылку на Swagger в README и комплекте для жюри. [Приёмка Swagger](<API/Swagger — Генерация и приёмка Analyst Days 23.md>)

## Поставка и выпуск

В репозитории подготовить Dockerfile сервиса, общий `compose.yaml`, снимок контракта OpenAPI и README с командами подготовки данных, запуска, проверок, деплоя и ссылкой на фронтенд. Сохранить использованные промпты без секретов. При pull request и изменении `main` проверить чтение SQLite, расчёт траектории и соответствие `app.openapi()` проектному YAML. После разрешения ссылок на схемы должны совпасть пути, методы, статусы, типы, обязательные поля и допустимые значения. После успешных проверок и сборки `main` опубликовать образ в GHCR с тегом по SHA.

Ручной `workflow_dispatch` принимает версии двух опубликованных образов, фиксирует их в журнале и разворачивает отдельный Compose-проект на Timeweb Cloud. SQLite монтируется с диска сервера только для чтения. HTTPS-прокси направляет `/` во фронтенд и передаёт `/api/*` в FastAPI с сохранением префикса. Исключить тела запросов и ответов с выбором из логов сервиса и прокси. Ключ сервера хранить в секрете окружения, доступном заданию деплоя.

На планируемом адресе `https://ad23-track.89.23.100.193.nip.io:8445/` извне проверить лендинг, health, выдачу обоих дней после перезапуска контейнеров и Swagger. Ошибка проверки означает неуспешный выпуск. Для отката повторно развернуть предыдущую рабочую пару образов с совместимым снимком. Рабочий срок сдачи — 21 ноября 2026 года до 12:00 МСК. Сайт и Swagger должны оставаться доступны до конца проверки жюри. [Порядок выпуска](<Деплой и CI-CD — Analyst Days 23.md>) · [Нефункциональные требования](<Нефункциональные требования — Analyst Days 23.md>)

Доведи работу до выкладки на Timeweb и проверки в Safari на этом Mac. Настрой окружение `timeweb` и секреты деплоя. Подготовь снимок SQLite и файлы первого выпуска, используй сохранённый TLS-сертификат. Дождись успешной публикации обоих образов в GHCR, включая фронтенд из параллельной сессии. Запусти workflow деплоя с SHA обоих коммитов и дождись его завершения. Затем открой публичный сайт и Swagger в двух вкладках Safari. На сайте проверь загрузку расписания, а в Swagger выполни `GET /api/program` через **Try it out** и проверь ответ `200`.
